# Contributing to UX Requirement Review

Use anonymized UX requirement examples and identify the original objective, affected people/tasks, the proposed solution, the reasoning being assessed, the strongest reasonable counterexample, and evidence that could change the result.

Focus on sound logic, correctly used UX research/human-factors concepts, understandable language and actionable decision boundaries. Do not overinterpret small samples, invent empirical findings or claim legal/standard violations without checking applicability.

Maintain equivalent Chinese and English professional guidance. The only current Skill entrypoint is `ux-requirement-review/SKILL.md`. Keep shared professional references consistent with the primary Skill entrypoint.

Never share personal identifiers, confidential workplace materials, participant data or unauthorized third-party text.
